# Halo: Combat Evolved (OpenCE)

Profile `opence-ce95f7de` in the external-engine catalog. The selector is `ports/halo`, published as `com.gamepkg.halo` in `ports/ports.gamepkglist`. The shipped target is `linux-i686`. `windows-i686` is a cross-compile. The package contains no Halo assets and no OpenCE source.

The host does not special-case this game. The record is `engines/halo/engine.toml`. A package names the profile and repeats the reviewed data layouts. Commands, image formats, license checks, the desktop sandbox, and game-data placement come from `src/external_engine`, which loads every `engines/*/engine.toml` the same way. Another port can add a catalog file without a new host module. Host Rust does not name this engine. The platform gap list is [docs/external-engine-platform-gaps.md](../../docs/external-engine-platform-gaps.md).

## What the generic path does

- `gamepkg build --engine-target <id>` selects a catalog target. On x86_64 Linux the default is `linux-x86_64`. `linux-i686` stays available with `--engine-target linux-i686`.
- A blocked target returns the upstream reason and does not fetch or compile.
- The source is `GAMEPKG_ENGINE_SOURCE` or `engine-sources/<profile>`. The checkout must be the pinned commit, the license digest must match, and game-data filenames are refused.
- Configure and build arguments live in the catalog. `{vctools}` and `{winsdk}` expand from `GAMEPKG_MSVC_TOOLS` and `GAMEPKG_WINDOWS_SDK`.
- The cache is `builds/<digest>/<profile>/<target>/` plus a `current` file. The executable must match the catalog image (ELF class and machine, or PE machine and magic). Companions get their own sha256 receipts.
- Play links a `link` layout's directories into a private content directory and sets the catalog data-root variable. A `beside` layout symlinks one archive next to the executable and leaves that variable unset. Changing the selection clears the catalog's cleanup directories.
- With `network = false` on Linux, bubblewrap starts the process with `--unshare-net`, a read-only `/`, and a writable runtime directory. Without bubblewrap it warns and starts directly. Windows is a direct spawn. A cached target for another OS is not launched.

## OpenCE entry

`linux-i686` runs upstream `configure.py --release --portable --pgo=off --lto=off` and `ninja linux`. The cache stores `halo` and `libSDL3.so.0`.

`windows-i686` runs the same configure with `--portable`, `--windows-cross`, and the two toolchain directories, then `ninja windows`. After checkout the host applies `engines/halo/patches/0003-x86-arch-and-portable-march.patch`, which makes a portable i686 Windows build pass `-msse2 -maes -mpclmul`. Clang 18's `i686-pc-windows-msvc` target does not define `__SSE2__` for `-march=x86-64`. `-march=native` enables SSE2 and is not portable. Linux i686 portable stays on `-march=x86-64`. The cache stores `halo.exe` and `SDL3.dll`. The PE already cached from the earlier `-march=native` build still matches the image check, so the host does not reconfigure it.

`linux-x86_64` is ready. `configure.py --arch x86_64` selects `x86_64-linux-gnu` and `-march=x86-64`. The portable x86_64 build compiles SDL3 with the host compiler. The Debian 11 i386 sysroot stays on `linux-i686`. `windows-x64` is ready. `configure.py --arch x86_64 --windows-cross` selects `x86_64-pc-windows-msvc`. Win64 is LLP64, so `long` is already 4 bytes. The link passes `/BASE:0x400000`, `/DYNAMICBASE:NO`, `/HIGHENTROPYVA:NO`, and `/FIXED` so a `halo_addr` round-trips. `_USE_32BIT_TIME_T` stays on the i686 Windows build and is omitted on Win64, because that CRT rejects it.

Patch `0001-pointer-independent-refs.patch` adds `halo_addr` (a 4-byte guest address) and static asserts for the Xbox on-disk sizes. Disc bytes stay 32-bit. Patch `0004-lp64-long-width.patch` stores Xbox `long` fields as `halo_s32`, which is 4 bytes on LP64 and is still `long` on i686 and Win64. Patch `0005-halo-addr-pointer-fields.patch` stores pointer fields in size-asserted structs as `halo_addr` and loads them with `halo_ref`. Patch `0006-lp64-layout-and-load-time-fixups.patch` converts the layout pointers that 0005 missed, keeps `unsigned long` fields that count 32-bit words as `halo_u32`, and fills pointer-to-`halo_addr` static initializers in a constructor at priority 100 on LP64 and Win64. On i686 those initializers stay compile-time casts. Both prefix `#error` guards are removed. Patch `0007-gamepkg-clock.patch` sends the monotonic game clock and `GetSystemTime` through `gamepkg_monotonic_time_ns` and `gamepkg_wall_time`. A weak definition still calls `clock_gettime` when the process is not linked to the host. `gamepkg_frame_time_us` stays the tick sample. Patch `0008-map-validate-layout.patch` stores `tools/map_validate.c`'s on-disk overlays as `halo_s32` and `halo_addr`, so `ninja linux` can build that tool on LP64. Patch `0009-gamepkg-threads.patch` sends `CreateThread`, `SleepEx`, and `SwitchToThread` through `gamepkg_thread_spawn`, `gamepkg_thread_sleep_ms`, and `gamepkg_thread_yield`. Mutexes, events, and completion handles stay in the engine. A weak definition still uses pthreads, `nanosleep`, and `pause` when the process is not linked to the host. `GAMEPKG_HOST_ABI` is 3. Patch `0010-gamepkg-directory.patch` sends map-folder stat, directory listing, and the `ui.map` header read through `gamepkg_path_stat`, `gamepkg_dir_open`, `gamepkg_dir_read`, and `gamepkg_path_read`. Handles are small integers. A weak definition still uses the operating system when the process is not linked to the host. `gamepkg_file_call` stays the player-picked import and export. Patch `0002-gamepkg-host-log.patch` sends `platform_log` through `gamepkg_host_log` in `include/gamepkg_host.h`. A weak definition still writes stderr when the process is not linked to the host. There is no `centrexity/OpenCE` fork. The patches are applied by the catalog after the pinned checkout. They are not pushed upstream.

Verified here: the portable Linux i686 ELF and the portable Linux x86_64 ELF both link, and a launch with a stand-in `ui.map` exits with OpenCE's own rejection (`ui.map version 0`). A cross build with Clang 18, `llvm-rc`, `lld`, and an `xwin splat --arch x86 --use-winsysroot-style` SDK produced `halo.exe` (PE32, machine `0x14c`, magic `0x10b`, about 20 MB) and `SDL3.dll`. GamePKG cached that image and refused to launch it on Linux. It was not executed under Wine. The same tools with `--arch x86_64` and an x64 splat produced `halo.exe` (PE32+, machine `0x8664`, magic `0x20b`, image base `0x400000`) and a 64-bit `SDL3.dll`. Under Wine that PE exits with `ui.map version 0` on the same stand-in map. Campaign, co-op, and multiplayer were not played: this machine has no Halo disc.

## Decisions

- OpenCE is fetched and built, not committed. The decompilation and all Halo maps stay out of git.
- The engine is a separate process with its own window. A Cube 2-style pixel bridge is not part of this profile.
- The portable Linux build needs network, so it is not the no-network bubblewrap compiler used for ordinary Rust packages. Playback can still drop the network through bubblewrap.
- Guest `network` stays false. Upstream multiplayer sockets are not wired through the GamePKG broker.
- The hard memory cap is 3 GiB because the engine is 32-bit. The library memory ceiling must be at least 2048 MiB.
- There is no catalog entry. Publishing one needs a real release asset URL, which this repository does not have.
