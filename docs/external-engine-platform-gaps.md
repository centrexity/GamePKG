# External engine platform gaps

Audit of the OpenCE profile (`engines/halo/engine.toml`, package `ports/halo`) against the host. The same host functions serve Linux and Windows on x86_64 and i686. Width-sensitive values in the C ABI are `uint32_t`, `int32_t`, and `uint64_t`. The header has no OS branch.

The host does not name this engine in Rust. `build.rs` embeds every `engines/*/engine.toml` and its `patches/*.patch` files. `src/external_engine` checks out the pinned commit and applies those patches. A test walks `src/**/*.rs` and rejects engine-specific tokens. The catalog record and `ports/halo/manifest.toml` are data: the manifest repeats the layouts and the memory numbers, and it cannot supply a compiler command.

OpenCE itself stays out of this repository. `centrexity/OpenCE` does not exist, and this run cannot create a fork, so the engine edits are the patch series under `engines/halo/patches/`. They apply on top of commit `ce95f7deed5bbf726e50a9d5fe5227437194cf3b`. Nothing is pushed to `OpenCommunityEdition/OpenCE`.

The C ABI is `include/gamepkg_host.h` (`GAMEPKG_HOST_ABI` 1), implemented in `src/engine_host.rs`. Each function calls the same service as the matching import in `wit/game.wit` and the Wasm wrappers in `src/runtime.rs`. Cube 2's frame bridge is a private byte pipe, and DOOM's file wrappers stay inside that port. This header is the native form of the shared host imports, not a second protocol. `gamepkg_host_log` is the one addition. Guests had no log import.

## What is converted, and what is left

Converted in this tree: the host record is data, the C ABI covers the shared host imports plus a log line and an RGBA frame submit, and six engine patches add the reference types, the log call, the architecture switch, the 32-bit Xbox `long`, `halo_addr` for pointer fields, and load-time fixups for the 64-bit static initializers.

Converted in patch 0004: Xbox `long` fields inside game structs, and `sizeof(long)` in those trees. On this checkout that was 3,354 fields across 373 files. `halo_s32` is a typedef of `long` on i686, Win32, and Win64, so those ABIs keep the old type. On LP64 it is `int`.

Converted in patch 0005: pointer fields inside size-asserted structs, 102 structs. Each field is `halo_addr`. A load is `((halo_ty_struct__field)halo_ref(slot))`. A store is `halo_ref_any`, which is the cast `((halo_addr)(value))` so a static initializer stays a constant expression on i686. A pointer above 4 GiB keeps only its low 32 bits.

Converted in patch 0006: the layout pointers 0005 did not see (nested anonymous fields, cache-file headers, `render_fog`, network client and server records, DirectSound slots, and `unsigned long` words that the Xbox counts as 32 bits). File-scope initializers that are not constant on LP64 or Win64 store 0 and a constructor at priority 100 writes the low 32 bits before `main`. Both prefix `#error` guards are removed. `linux-i686`, `linux-x86_64`, and `windows-x64` link, and each stand-in `ui.map` exits with `ui.map version 0` (`windows-x64` under Wine). 64-bit targets passing that check: 2 of 2. Platform calls moved onto the GamePKG C ABI: 0 of 7 (clock, threads, directory VFS, window, draw, input, audio). The log call was already on the ABI.

Not converted: the platform calls that still use SDL, OS files, OS threads, and OS clocks. Pointers that are not part of an Xbox-sized struct stay native pointers. An out-parameter that writes a native pointer into a `halo_addr` slot is still the wrong width on LP64 and LLP64.

The reference test `engines/halo/ref/test_halo_ref.c` (the same bytes as patch 0001, with the `halo_addr` typedef guarded when `halo_layout.h` is already included) was compiled and run for Linux x86_64 and Linux i686, and compiled for `i686-pc-windows-msvc` and `x86_64-pc-windows-msvc`. The static asserts are part of that translation unit. The Linux x86_64 engine binary links and passes the stand-in check. The Win64 PE links and passes the same check under Wine.

## Build evidence for the march split

On Clang 18, `-dM` for a translation unit that does not include a header:

- `i686-pc-windows-msvc -march=x86-64` defines `__SSE__` and does not define `__SSE2__`.
- `i686-pc-windows-msvc -msse2 -maes -mpclmul` defines `__SSE2__`, `__AES__`, and `__PCLMUL__`.
- `x86_64-pc-windows-msvc -march=x86-64` defines `__SSE2__`.
- `i686-linux-gnu -m32 -march=x86-64` is unchanged from the flags that already built the portable Linux i686 ELF.

The catalog's `windows-i686` configure now passes `--portable`. The cached `halo.exe` under `/tmp/OpenCE-win` was produced before that flag and still matches the PE image check, so the host does not reconfigure it. A clean configure applies patch 0003 first, then `-msse2 -maes -mpclmul`.
