See the source, review permissions, and verify the creator before you play. GamePKG builds your chosen packages locally and limits their access through an isolated runtime. GamePKG is a package format and player; creators host their own games, and you choose where to obtain them.

A game package you can inspect.

An opaque executable is difficult to review. When launched without a sandbox, it may inherit your account's access to files, network connections, and other programs. GamePKG brings source visibility, signed contents, restricted builds, and declared capabilities into one workflow.

Each .gamepkg carries Rust source, Slang shader source, assets, and a signed manifest. You can inspect its code and permissions before installing it. Source visibility makes review possible; it does not prove safety. Conventional signed binaries and separately sandboxed apps can also offer protections.

Build here. Improve over time.

Source transparency also gives you control over the build. Compile on demand with configurable optimization settings, then rebuild when your settings or compiler tools change. Performance depends on the game, settings, and host runtime.

Check for creator-signed updates yourself or set periodic checks while the library is idle. Review each update before installing it; rebuilding uses the same source checks and isolated compiler boundaries.

What can a game access?

The runtime design starts with no ambient filesystem or network access. Games receive specific operations through a small host API. The host scopes those operations to the signed package permissions and explicit user selections.

  • Assets: virtual paths inside the game's archive, rather than unrestricted access to your folders.
  • Input, rendering, and audio: explicit game operations exposed by the host.
  • Saves: host-scoped storage rather than arbitrary filesystem writes.
  • ROMs: a signed manifest declares which ROM files must be supplied by the player. No ROM is fetched automatically; only the files selected by the player are shared read-only in the signed manifest’s order for that session.
  • Networking: guest networking is unsupported. Manifests must declare network = "none".

Installing a package runs no game code or package-provided install scripts. Source checks reject filesystem, network, process, and environment paths, compile-time file includes, macros, unsafe blocks, and foreign declarations. Source checks, compiler isolation, and runtime limits work together; inspection alone cannot prove a game harmless.

Build your library at your own pace.

Your library tracks time played, locally earned achievements, and storage used. Signed game manifests can declare achievements and an estimated storage requirement; measured usage and creator estimates are shown separately.

The desktop library periodically checks installed games for verified updates. Settings controls the interval or disables checks. Available updates stay ready for your review; installation is always your choice.

Import a portable .gamepkgstore bundle to bring games and their shared assets into your library. Inspect the verified games and creator keys first, then approve installation. Settings also controls approval of bundled game libraries.

Import a .gamepkglist to add many games without downloading them. Entries stay Not downloaded until you choose one. Catalog claims are unverified; the downloaded, signed package supplies the authoritative identity and permissions.

User-requested downloads support HTTPS and Tor onion URLs. Onion downloads go through a local Tor SOCKS proxy with remote DNS and no direct fallback. Host downloads and update checks do not grant game code network access.

Updates keep continuity with the creator key approved at installation. A signature proves integrity and key ownership, not a creator's real-world identity or the safety of their code.

Download from a GitHub project

Enter https://github.com/owner/repository to download its latest published stable release. The release must contain exactly one .gamepkg file. A /releases/tag/version link selects a specific release; use a direct asset link when the project hosts multiple packages. GitHub project links also work in game catalogs and signed update URLs. For list or store imports, the app selects one matching .gamepkglist or .gamepkgstore release file. Package signatures, creator approval, and update checks still apply.
