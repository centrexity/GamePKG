Approved game libraries.

Games can use only libraries in the host’s bundled, pinned catalog that you have approved. Adding an approval cannot authorize an arbitrary crate or download new code.

Bundled catalog

Only these host-owned wrappers are allowed, each pinned to 0.1.0 with default features disabled and no extra features or transitive dependencies:

  • gamepkg-input: keyboard, controller and touchscreen button input.
  • gamepkg-file: scoped assets, selected ROMs and saves.
  • gamepkg-window: drawing into the host viewport.
  • gamepkg-networking: denied requests under the no-network policy.
  • gamepkg-byteorder: explicit-endian u32 reads and writes.

A matching prefix grants no approval. Raw third-party crates and unknown gamepkg-* names are rejected. The host supplies pinned source offline and rejects replacements. The signed lockfile must match the exact host-owned graph. Run gamepkg allowlist list for source hashes and read the developer instructions for the checklist, declarations, examples and migration steps.

Choose your approvals

Open Settings → Approved game libraries, change each library’s checkbox, then choose Save settings. Cancel discards edits. The desktop and CLI share these preferences.

gamepkg allowlist list
gamepkg allowlist remove gamepkg-byteorder
gamepkg allowlist add gamepkg-byteorder

Removing approval blocks verification, installation, builds, and new play sessions for games that depend on that library. It does not interrupt a game already running. Games without dependencies continue to use the same source and runtime restrictions.

What source packages cannot do

Guest packages cannot use build scripts, procedural macros, path or Git dependencies, unapproved transitive dependencies, extra dependency features, or binary includes. Every packaged Rust source file is checked, including unused modules. Unsafe guest code and ambient filesystem, network, and process operations are rejected.

Linux builds use locked, offline Cargo in an isolated process without the user’s home directory or network access. Runtime games receive scoped host operations under Wasmtime. Source scanning is a policy filter; build and runtime isolation enforce additional boundaries.

Adding a library to the catalog

The catalog contains the five pinned entries above. An unknown name passed to allowlist add is rejected. A new library requires a host update that reviews and bundles its source, pins its complete dependency graph, and tests its permitted build configuration. A creator cannot expand the catalog through a game manifest.

Approval and signatures do not guarantee harmless code. The host, compilers, and graphics drivers remain trusted components. Review the creator and permissions before installation.
