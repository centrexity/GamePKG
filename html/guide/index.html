Start playing with GamePKG.

Inspect the creator and permissions, build the game on your machine, then play through the host’s scoped runtime.

Development preview. Local builds currently require Linux and the tools below. Supported games play in the desktop library; broader graphics and builds on other operating systems remain unfinished.

Set up the host

Get the repository and installation prerequisites. Install Rust with the Wasm target, the Linux isolation tools, audio development headers, and the pinned Slang compiler. The repository’s README has the full setup commands.

cargo build --locked --release --all-features --bins
./target/release/gamepkg-gui

In Settings, enter your Slang 2026.19 installation folder. New configurations use GLSL so supported shader games can render in the desktop player. Set your library folder, memory ceiling, sound volume, and update-check interval, then choose Save settings.

Inspect, install, build, play

  1. In Library, enter a local .gamepkg path or a creator’s HTTPS download URL. Choose Download / inspect.
  2. Review the verified creator fingerprint, version, permissions, resource limits, and ROM requirement. You do not need to enter a signing key. Confirm the creator before choosing Trust this creator and install.
  3. Choose Build in the game’s row. Compilation runs in an isolated environment. A failed initial build leaves the game unbuilt and displays an error. A failed rebuild preserves the earlier build.
  4. Choose Play when the build succeeds. Use Rebuild after changing build options or shader backend.

A signature proves key ownership and integrity; it does not prove the creator’s real-world identity or guarantee harmless code. Games receive scoped host operations, not general access to your folders or network.

Games that need your ROM

Enter the path to your own ROM file in the Library ROM field before playing a game marked User ROM required. Only that file’s read-only session snapshot is shared. The host does not fetch a ROM or grant folder access.

Add several games

Import a .gamepkglist to add catalog entries without downloading games. Choose a game’s Download / inspect action when ready. Catalog claims remain unverified until its package is checked.

For a .gamepkgstore, choose Inspect .gamepkgstore bundle, review the listed games and creator keys, then approve installation. A store bundle includes its required shared assets. Inspection and cancellation install nothing.

Updates and Tor

Use Check for updates or enable periodic checks in Settings. Checks verify candidate updates while the library is idle; updates require your installation choice and must keep the game’s approved creator key.

For onion URLs, run Tor separately and enter its loopback SOCKS proxy in Settings. DNS resolves through the proxy. Missing Tor connectivity fails the download; it never falls back to a direct connection.

Try a source example

Creators can build a local example into a signed source package. Keep the private key private; players need no key entry.

./target/release/gamepkg keygen -o creator.key
./target/release/gamepkg build examples/good/collect-stars \
  -o /tmp/collect-stars.gamepkg --key creator.key

Inspect /tmp/collect-stars.gamepkg in the desktop library, then follow the install, build, and play steps above. The creator build checks compilation before publishing the package; it does not install it automatically.

Download from a GitHub project

Enter https://github.com/owner/repository to download its latest published stable release. The release must contain exactly one .gamepkg file. A /releases/tag/version link selects a specific release; use a direct asset link when the project distributes multiple games. GitHub project links also work in game catalogs and signed update URLs. For list or store imports, the app selects one matching .gamepkglist or .gamepkgstore release file. Package signatures, creator approval, and update checks still apply.

Integrity checks and repair

Use Check integrity in the library, or gamepkg integrity-check GAME_ID, to check signed package contents, shared assets and compiled game checksums. Fix / rebuild recompiles verified source; damaged archives can be restored from the verified local recovery copy. Missing or damaged recovery copies require a verified replacement original. Player saves and history are preserved.

Multiple ROM files

Games can declare up to eight player-provided ROMs. Add each file in manifest order using Add ROM file, or repeat --rom FILE in the CLI. Files are shared as read-only snapshots without exposing their host paths.
